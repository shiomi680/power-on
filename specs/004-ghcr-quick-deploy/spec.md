# 機能仕様書: ghcr.io プリビルト・イメージ・ワンコマンド・デプロイメント

**フィーチャーブランチ**: `004-ghcr-quick-deploy`

**状態**: ドラフト  
**入力**: ユーザー説明：「ghcr イメージを使ったワンコマンド・デプロイメント。docker pull して即座に起動。ローカルビルドは代替方法。」

## ユーザーシナリオ・テスト *(必須)*

### ユーザーストーリー 1 - デプロイ初心者向けワンコマンド・デプロイ (優先度: P1)

初心者ユーザーが docker pull + docker compose up だけで、ビルド不要に即座にシステムを起動したい。

**優先度理由**: デプロイ・ハードルを最小化し、ユーザー体験を大幅に向上させるため。事前にテストされたイメージが利用可能。

**独立テスト**: README（または ドキュメント）に、ghcr.io からのイメージ取得・起動手順が明確に記載され、実際に docker pull + docker compose up でシステムが起動できることで検証。

**受け入れシナリオ**:

1. **Given** Docker がインストール済み、**When** ghcr.io イメージの取得手順を従う、**Then** イメージが正常にダウンロード・ロードされ、コンテナレジストリで確認可能
2. **Given** イメージが準備完了、**When** docker compose up -d でサービス起動、**Then** 2分以内に両サービス（RPi-WOL、PC-API）が稼働中
3. **Given** サービス起動後、**When** ヘルスチェック・エンドポイントにアクセス、**Then** 正常な応答が返される

---

### ユーザーストーリー 2 - 本番デプロイメント向けバージョン・ピン (優先度: P1)

本番運用ユーザーが、特定の検証済みイメージバージョンをピン指定してデプロイしたい。

**優先度理由**: 本番環境の安定性・再現性を確保するため。ローリング・バージョンは予測不可能な更新を防止。

**独立テスト**: docker-compose.yml で特定のバージョン・タグ（例：`ghcr.io/shiomi680/power-on-rpi:v1.0.0`）を指定し、そのバージョンが起動可能であることで検証。

**受け入れシナリオ**:

1. **Given** docker-compose.yml に具体的なバージョン・タグを指定、**When** docker compose up を実行、**Then** 指定されたバージョンのイメージが起動される
2. **Given** 異なるバージョン・タグが指定可能、**When** タグ切り替え、**Then** 対応するバージョンが起動される

---

### ユーザーストーリー 3 - ローカル・ビルド代替路 (優先度: P2)

開発者が、カスタマイズやコード修正後、ローカル・ビルド・オプションで独自イメージを作成したい。

**優先度理由**: 開発フローの拡張性。ghcr.io イメージは利便性、ローカル・ビルドは柔軟性を提供。

**独立テスト**: README（または ドキュメント）に、docker build ワークフローが記載され、ローカル・ビルド・イメージで起動可能であることで検証。

**受け入れシナリオ**:

1. **Given** docker build コマンドが提供、**When** イメージをビルド、**Then** 正常にビルド完了・実行可能なイメージが生成される
2. **Given** ローカル・ビルド・イメージ、**When** docker compose で参照、**Then** ローカル・イメージから正常に起動される

## 前提条件

- ghcr.io に docker イメージが既にアップロード済み（CI/CD パイプラインで自動化）
- Docker クライアント（v20.10+）がインストール済み環境を想定
- イメージはパブリック・レジストリ（認証不要）として利用可能
- 既存のデプロイメント・ドキュメント（README.md）で更新対応
- ローカル・ビルド・パス（Dockerfile、docker-compose.yml）は継続利用可能
- docker-compose.yml は git リポジトリに単一の出典として保存

## デプロイメント・アプローチ

**方式**: Git Clone（シンプル）
- docker-compose.yml は git repository で管理
- ユーザーは git clone してそのまま使用
- Release assets への含含は行わない（複雑性回避）

**フロー**:
```bash
git clone https://github.com/shiomi680/power-on
cd power-on
cp .env.example .env
# (編集: PC_ADDRESS、WOL_TARGET_MAC を環境に応じて設定)
docker compose up -d
```
